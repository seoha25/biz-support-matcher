# Biz Support Matcher 기능 정의서 

## 1. 문서 개요

- 프로젝트명: Biz Support Matcher
- 서비스명: AI 기반 소상공인·중소기업 지원사업 매칭 플랫폼
- 작성 목적: 프로젝트의 주요 기능과 개발 범위를 정의하고 이후 화면 설계, ERD, API 명세 및 개발의 기준으로 사용한다.

---

## 2. 프로젝트 개요

### 2.1 프로젝트 목적

정부, 지방자치단체 및 유관기관에서는 다양한 소상공인·중소기업 지원사업을 제공하고 있다.

하지만 공고의 수가 많고 지원대상, 지역, 업종, 업력 등 조건이 달라 사용자가 자신에게 적합한 지원사업을 찾기 어렵다.

Biz Support Matcher는 공공데이터 API를 통해 지원사업 공고를 수집하고 사용자가 등록한 사업체 정보를 기반으로 지원 가능성이 높은 사업을 선별한다.

이후 AI를 활용하여 지원사업의 세부 내용을 분석하고 사용자에게 지원사업 적합도와 추천 이유를 제공하는 것을 목표로 한다.

---

## 3. 서비스 대상

### 3.1 비회원

회원가입하지 않은 사용자이다.

사용 가능한 기능:

- 지원사업 목록 조회 
- 지원사업 검색
- 지원사업 필터링
- 지원사업 상세 조회

### 3.2 회원

서비스에 가입하고 로그인한 사용자이다.

비회원 기능을 포함하여 다음 기능을 추가로 사용할 수 있다. 

- 사업체 정보 등록
- 사업체 정보 수정
- 맞춤 지원사업 추천
- AI 적합도 분석
- 관심 지원사업 저장
- 관심 지원사업 조회
- 관심 지원사업 삭제

## 5. 사업체 정보

맞춤형 지원사업 추천을 위해 회원으로부터 사업체 관련 정보를 입력받는다.

현재 고려 중인 정보는 다음과 같다.

| 항목          | 설명                                        | 매칭 활용 |
|---------------|---------------------------------------------|---|
| 사업체명      | 사용자가 운영하는 사업체명                  | 기본정보 |
| 사업자 유형   | 개인사업자, 법인사업자 등                   | 지원대상 판단 |
| 기업 유형     | 소상공인, 중소기업 등 기업 규모에 관한 정보 | 지원대상 판단 |
| 업종          | 음식점업, 제조업, IT 등                     | 업종 조건 판단 |
| 사업장 지역   | 시·도 및 시·군·구                           | 지역 조건 판단 |
| 사업 시작일   | 사업 개시일                                 | 업력 계산 |
| 직원 수       | 상시 근로자 수                              | 기업 규모 판단 |
| 매출 규모     | 연간 매출액 구간                            | 일부 지원사업 조건 판단 |
| 관심 지원분야 | 경영, 금융, 기술, 창업, 수출 등             | 추천 우선순위 |

공공데이터의 실제 지원사업 조건을 분석한 후 필요한 사용자 정보만 최종 선정한다.

※ 기업 유형은 사용자가 직접 선택하도록 할지, 입력된 사업체 정보를 기준으로 시스템에서 판단할지 추후 설계 단계에서 결정한다.

주요 활용 정보:

| 데이터  | 설명 |
|---------|---|
| 공고 ID | 공고의 고유 식별값 |
| 공고명 | 지원사업 공고 제목 |
| 공고 URL | 원본 공고 상세 페이지 |
| 소관기관 | 사업을 담당하는 소관기관 |
| 수행기관 | 실제 사업 수행기관 |
| 사업개요 | 지원사업에 대한 상세 설명 | 
| 지원분야 | 경영, 기술, 금융, 창업, 수출 등 |
| 지원대상 | 소상공인, 중소기업, 창업기업 등 |
| 신청기간 | 지원사업 접수기간 |
| 등록일 | 공고 등록일 |
| 수정일 | 공고 수정일 |
| 해시태그 | 공고와 관련된 키워드 |
| 신청방법 | 이메일, 방문, 온라인 등 신청 방법 |
| 문의처 | 담당기관 연락처 |
| 신청 URL | 실제 사업 신청 페이지 |
| 첨부파일 | 공고문 및 신청서 파일 |

공공데이터 API의 실제 응답에서 공고 고유 ID, 공고명, 사업개요, 지원분야, 신청기간, 지원대상, 해시태그, 신청방법 및 신청 URL 등의 데이터를 확인하였다.

## 7. 지원사업 수집 처리

공공데이터 API에서 지원사업을 조회한 뒤 공고 ID를 기준으로 데이터를 관리한다.

### 신규 공고 

DB에 해당 공고 ID가 존재하지 않는 경우 신규 지원사업으로 판단하여 저장한다. 

### 기존 공고 

동일한 공고 ID가 이미 존재하지만 공고 내용 또는 수정일이 변경된 경우 기존 데이터를 갱신한다.

### 중복 공고 

동일한 공고 ID이며 변경사항이 없는 경우 추가 저장하지 않는다.

처리 흐름:

공공데이터 API 호출 

-> 지원사업 목록 수신 

-> 공고 ID 확인

-> 신규 공고 여부 확인 

-> 신규 공고 저장 또는 기존 공고 갱신

## 8. 지원사업 기본 매칭 

AI 분석 전에 명확하게 판단할 수 있는 조건을 이용하여 지원사업 후보를 먼저 선별한다. 

예상 비교 조건:

- 모집 여부 
- 지역
- 사업자 유형
- 기업 유형
- 업종
- 업력
- 기업 규모
- 지원분야

예시:

전체 지원사업

-> 현재 신청 가능한 사업 필터링

-> 지원대상 비교 

-> 지역 조건 비교

-> 업종 조건 비교

-> 관심 지원분야 비교

-> AI 분석 대상 후보 생성

기본적인 자격조건은 프로그램 로직을 이용하여 처리하고 문맥 분석이 필요한 조건을 AI가 분석하도록 한다.

## 9. AI 매칭

기본 조건 매칭을 통과한 지원사업을 대상으로 AI가 사용자 사업체 정보와 공고 내용을 비교한다.

AI 분석 결과는 다음 정보를 제공한다. 

### 적합도 

예:

`92점`

### 추천 이유 

예: 

- 소상공인 대상 사업과 일치
- 사용자의 사업장 지역과 지원지역이 일치 
- 관심 지원분야인 마케팅 지원 포함
- 현재 신청 가능한 지원사업

### 확인 필요 사항 

예:

- 일부 세부 업종 제한은 원문 공고 확인 필요
- 특정 인증서 보유 여부 확인 필요

AI의 판단은 최종적인 지원 가능 여부를 확정하지 않는다.

최종 신청 가능 여부는 사용자가 실제 공고문의 세부 자격 조건을 확인하도록 안내한다.

## 14. 개발 시 고려사항

### 외부 API 데이터와 서비스 데이터 분리 

공공데이터 API에서 내려오는 응답 구조와 서비스 내부 DB 구조를 동일하게 만들지 않는다. 

외부 API 응답 DTO와 서비스 내부 Entity를 분리한다.

### API Key 보안

공공데이터 API Key와 AI API Key는 코드에 직접 작성하지 않고 환경변수로 관리한다.

GitHub Repository에 인증키가 포함된 파일을 업로드하지 않는다.

### AI 역할 제한

명확하게 비교할 수 있는 지역, 기업 유형, 모집상태 등의 조건은 일반 프로그램 로직에서 처리한다. 

자연어 해석이 필요한 지원조건과 사업내용 비교에 AI를 활용한다.

### AI 결과 안내 

AI 분석 결과를 실제 지원 가능 여부로 확정해서 표시하지 않는다.

사용자가 최종적으로 공고문의 세부 지원조건을 확인하도록 안내한다.
