# Biz Support Matcher 프로젝트 구조

## 1. 문서 개요

- 프로젝트명: Biz Support Matcher
- 목적: 프로젝트의 패키지 구조와 각 영역의 역할을 정의하여 일관된 구조로 개발하기 위한 기준으로 사용한다.

---

## 2. 기술 스택

### Backend
- Java 17
- Spring Boot
- Spring Security
- MyBatis

### Database
- MySQL 8

### External API
- 공공데이터포털 중소기업 지원사업 공고 조회 API
- AI API

### Build
- Gradle

---

## 4. 패키지 역할

### global

프로젝트 전체에서 공통으로 사용하는 기능을 관리한다.

- `config`: 애플리케이션 공통 설정
- `exception`: 공통 예외 및 예외 처리
- `security`: 로그인 및 인증/인가 관련 처리

### user

회원 관련 기능을 담당한다.

- 회원가입
- 로그인
- 로그아웃
- 회원정보 조회
- 회원정보 수정
- 회원 탈퇴

### business

회원이 등록한 사업체 정보를 관리한다.

- 사업체 등록
- 사업체 조회
- 사업체 수정
- 관심 지원분야 관리

### announcement

지원사업 공고 조회 기능을 담당한다.

- 지원사업 목록 조회
- 키워드 검색
- 조건별 필터링
- 정렬
- 지원사업 상세 조회

### favorite

회원의 관심 지원사업을 관리한다.

- 관심사업 등록
- 관심사업 목록 조회
- 관심사업 삭제

### matching

사용자의 사업체 정보와 지원사업 조건을 비교하는 기본 매칭 로직을 담당한다.

주요 비교 조건:

- 모집 상태
- 지역
- 사업자 유형
- 기업 유형
- 업종
- 업력
- 기업 규모
- 관심 지원분야

기본 조건을 통과한 지원사업을 AI 분석 대상으로 전달한다.

### ai

기본 매칭을 통과한 지원사업에 대해 AI 기반 분석을 수행한다.

- AI 적합도 분석
- 적합도 점수 생성
- 추천 이유 생성
- 일치 조건 제공
- 확인 필요 조건 제공
- 부적합 이유 제공

AI 분석 결과는 최종적인 지원 가능 여부를 확정하지 않는다.

### collection

공공데이터 API를 이용한 지원사업 데이터 수집을 담당한다.

- 공공데이터 API 호출
- 신규 공고 저장
- 기존 공고 갱신
- 중복 공고 확인
- 자동 수집
- 수집 결과 기록

사용자가 직접 호출하는 기능이 아닌 시스템 내부 기능으로 구성한다.

## 5. 계층별 역할

각 도메인은 필요한 경우 다음 계층으로 구성한다.

### controller

클라이언트의 HTTP 요청을 받고 응답을 반환한다.

### service

비즈니스 로직을 처리하고 필요한 Mapper를 호출한다.

### mapper

MyBatis를 이용하여 데이터베이스 접근을 담당한다.

### dto

API 요청 및 응답 데이터와 외부 API 데이터를 전달하는 객체를 관리한다.

### domain

데이터베이스 테이블과 대응되는 도메인 객체를 관리한다.

## 6. Resources 구조

MyBatis SQL Mapper와 애플리케이션 설정 파일을 관리한다.

```text
src/main/resources
│
├── mapper
│   ├── UserMapper.xml
│   ├── BusinessMapper.xml
│   ├── AnnouncementMapper.xml
│   ├── FavoriteMapper.xml
│   ├── MatchingMapper.xml
│   ├── AiAnalysisMapper.xml
│   └── CollectionMapper.xml
│
└── application.yml
```

공공데이터 API Key 및 AI API Key와 같은 인증정보는 소스코드에 직접 작성하지 않고 환경변수를 통해 관리한다.

---

## 7. 기본 요청 처리 구조

일반적인 API 요청은 다음 흐름으로 처리한다.

```text
Client
   ↓
Controller
   ↓
Service
   ↓
Mapper
   ↓
MySQL
```

외부 API를 사용하는 기능은 다음과 같은 흐름으로 처리한다.

```text
공공데이터 API / AI API
          ↓
       Service
          ↓
        DTO
          ↓
       Mapper
          ↓
        MySQL
```

## 8. 설계 원칙

- 도메인별로 패키지를 분리하여 기능의 책임을 명확하게 한다.
- Controller에서는 비즈니스 로직을 직접 처리하지 않는다.
- Service에서 주요 비즈니스 로직을 처리한다.
- 데이터베이스 접근은 MyBatis Mapper를 통해 수행한다.
- API 요청/응답 객체와 DB 도메인 객체를 분리한다.
- 외부 API 응답 DTO와 내부 도메인 객체를 분리한다.
- 공통 설정과 예외 처리는 `global` 영역에서 관리한다.
- API Key 및 민감정보는 환경변수로 관리한다.
